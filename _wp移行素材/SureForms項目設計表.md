# SureForms 項目設計表（お問い合わせ／予約 兼用フォーム）

現行 `contact.html` のフォームを **SureForms** で再現するための設計書です。
**予約導線もこのフォームに統一**（「ご相談の種類＝初回体験を申し込みたい」で受付）。

---

## 1. フォーム全体

| 項目 | 内容 |
|------|------|
| フォーム名 | お問い合わせ（初回体験・ご相談） |
| 設置先 | 固定ページ「お問い合わせ」 |
| 導線 | 全ページの「**ご予約はこちら**」ボタン → このページ |
| 送信先メール | **aspathlife@gmail.com** |

### 「ご相談の種類」の選択肢（順序どおり）
1. **初回体験を申し込みたい**（初期選択）
2. サービス内容について質問したい
3. 料金について相談したい
4. 取材・講演・お仕事のご依頼
5. その他のお問い合わせ

> ⚠ **「必須」バッジを表示するのは #1・#2・#3・#4・#7・#8・#9 のみ**。メール／電話／知りましたか／メッセージには「必須」「任意」いずれのバッジも表示しない（現行仕様）。

## 3. 条件分岐（SureForms の Conditional Logic）

| ルール | 条件 | 対象 |
|--------|------|------|
| A | `inquiry_type` = **初回体験を申し込みたい** → **表示** | #4〜#12（生年月日・メール・電話・住所・どなた・診断名・診断名その他・困りごと・知りましたか） |
| B | `inquiry_type` ≠ 初回体験を申し込みたい → **表示** | #13・#14（メール／電話） |

- ルールAで表示される必須項目（#4/#7/#8/#9）は、**非表示時に必須解除**されること（＝初回体験以外では送信をブロックしない）を必ずテストで確認。
- #5/#6（初回体験時のメール/電話）と #13/#14（それ以外のメール/電話）は**別フィールド**。メール本文では両方を出力しておけば、どちらか入力された方が入ります。

## 7. 【旧】新構成（2025-07-25 打合せ反映）— 問い合わせを2フォームに分離

> §1〜§6 は当初の「1フォーム・5択・条件分岐」案。**下記が最新の確定構成**です（実装はこちらを優先）。

### 7-1. お問い合わせフォーム（公開：`/contact/`）
- ご相談の種類は **2択のみ**：`初回体験を申し込みたい` / `その他のお問い合わせ`
- **初回体験を選択** → フォームは表示せず、**公式LINE登録を促すブロック**（メッセージ＋LINEボタン）を表示。申込は下記の限定フォームへLINE経由で誘導
- **その他を選択** → メッセージフォーム（お名前【必須】・フリガナ【必須】・メール・電話・メッセージ）を表示 → `aspathlife@gmail.com` へ送信
- 実装：SureForms の条件分岐で「初回体験時＝LINE案内ブロック表示／フォーム非表示」。または LINE案内は固定ブロック＋その他選択時のみフォーム表示。

### 7-2. 初回体験 お申し込みフォーム（限定公開：`trial-entry` 相当）
- **公開しない・リンクしない・noindex**。公式LINEの自動メッセージで配布する**限定URLからのみ到達**。
- ページはヘッダー/フッター無しの**フォーム単体**（dev: `trial-entry.html`）。
- 収録項目（＝§2の初回体験項目）：お名前【必須】／フリガナ【必須】／生年月日【必須】／**メール【必須】**／電話／ご住所【必須】／どなた【必須】／診断名【必須】／診断名その他／困っていること／知ったきっかけ／メッセージ
- **メールは必須**（申込者へ控えを送るため）。
- **送信時に2通のメールを送る**：
  1. **山口様への通知メール**（`aspathlife@gmail.com`）… 全入力項目を記載。件名 `【初回体験】ASPATH お申し込み／{お名前}様`
  2. **申込者への控えメール**（申込者のメールアドレス宛）… 入力内容のコピー＋受付案内。件名 `【ASPATH】初回体験のお申し込みを受け付けました`
- SureForms の「メール設定」で通知先と自動返信（控え）の2つを設定する。

### 7-3. 限定URLの発行方法（WordPress・移行後に設定）
公式LINEに載せる「限定公開URL」の作り方（いずれか）:

| 方式 | 内容 | 向き |
|------|------|------|
| **限定公開（推奨）** | 推測されにくいスラッグで公開＋noindex＋メニュー/サイトマップ除外。1本の固定URLをLINE自動メッセージに掲載 | 手軽・運用シンプル |
| **パスワード保護** | WP標準のページパスワード。LINEでURL＋合言葉を配布。URLだけでは開けない | より安全 |
| **トークン付きURL** | プラグインで都度発行・期限付き・一人一URL | 申込者ごとに個別発行したい場合 |

> **確定方針：原則「限定公開」**（推測されにくいスラッグ＋noindex＋メニュー/サイトマップ除外の1本の固定URL）。より高い秘匿が必要になった場合のみパスワード保護／トークン方式を検討。
